# 给模型加外挂：模型、工具与应用的分工

模型负责根据上下文生成文字或工具调用。应用负责提供资源、验证参数、执行操作、管理状态并将结果交还模型。外接 API 不会自动扩充模型权重，也不会让本地模型获得云端厂商的所有托管功能。

## 已实现的两个例子

### 结构化工具调用

运行 `examples/tool_agent.py`，应用声明 `calculate(expression)` 的 JSON schema；模型通过 Ollama `tool_calls` 发出调用；程序使用 AST 白名单仅计算数字与四则运算，把结果作为 `role=tool` 消息回填，再由模型组织回答。

测试输入 `(123+456)*7` 的程序真实返回 `4053`，验证脚本同时检查工具执行结果与最终答案，不仅检查模型是否说出了数字。有限步数避免无限循环；不使用 `eval`、任意 shell 或动态导入。

参考美食 Agent 的做法还可以外接菜谱查询、库存查询和企业业务函数。把工具数据当作证据仍需检查来源、新鲜度、单位和适用范围。

### RAG 知识库

运行 `examples/rag.py`，先检索 `knowledge/*.md`，再把匹配片段与问题交给模型。输出独立的 `sources` 列表，便于核对模型引用。

本例采用中文二元词重叠，优点是可离线、无需新模型和数据库；缺点是同义词召回与长文档检索能力有限。语义检索可进一步换成 Ollama embedding 模型：文档切块、调用 `/api/embed` 生成向量、用向量库检索、可选 reranker 重排，再把片段交给生成模型。embedding 模型与聊天模型可以不同，不能把生成模型的答案当作向量。

## 可扩展的能力

| 需求 | 外挂组件 | 应用要承担的工作 |
|---|---|---|
| 查看最新资料 | 搜索 API、网页提取或浏览器 | 返回可核对的来源；区分网页内容与可信指令 |
| 连接多个工具平台 | MCP 客户端与 MCP servers | 发现工具、转换 schema、认证、调用并回传结果；不是让模型直接连 MCP |
| 跨对话记忆 | SQLite/Postgres/向量库 | 在授权范围内存取；提供删除和更新能力 |
| 数据查询 | 只读数据库工具 | 参数化查询、限定表与行数，避免执行任意 SQL |
| 数据分析与代码 | 沙箱运行器 | 隔离目录、网络和计算资源；不直接在宿主机执行未知代码 |
| 看图与语音 | 视觉模型、OCR、ASR、TTS | 检查模型模态支持；音频可走独立转写/合成流水线 |
| 更稳定的输出 | JSON schema、验证器、评测集 | 校验格式、事实与工具结果，失败时有限次重试 |
| 多步骤业务任务 | Agent/工作流框架 | 设置步骤预算、可恢复状态、明确有副作用工具的权限 |
| 特定领域适配 | LoRA/微调 | 数据准备与训练；这类改变权重，和普通工具外挂不同 |

MCP 是工具连接协议；RAG 是检索与上下文组织方式；Agent 是应用的循环和编排方式；LoRA 是训练方法。这些概念可以组合使用。

接口选择建议：只做本地 Ollama 调参用原生 API；复用现有聊天 SDK 用 Chat Completions；应用围绕 typed output items 构建时用 Responses；客户端已使用 Anthropic Messages 时用 Messages。无论接口，工具最终均由应用执行，功能上限取决于模型能力和服务实现。
